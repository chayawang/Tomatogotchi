# v1.0.2 public prerelease (build31)

[繁體中文](v1.0.2.md) · [English](v1.0.2.en.md) · [日本語](v1.0.2.ja.md)

Official downloads: https://github.com/chayawang/Tomatogotchi/releases

Includes custom round durations, an 80% device body, short-range work animations, actual 2D walks on the current desktop, five species, and tombstone records. This is the first public source and downloadable test release; it does not claim complete manual verification of all native interactions.

## Build and verification

Version 1.0.2, build31, arm64 (Apple Silicon). The declared minimum is macOS 13; the physical test baseline is Apple Silicon/macOS 14.4.1. See the package's release-metadata.json and official Release page for the source commit, signing status, and architecture.

The canonical automated entry is `bash scripts/verify.sh`. It covers core/shared App models, save compatibility/death/growth, work/walking, 1,790 character renders across five species, 72 device/button renders, 12 memorial screens, 120 new asset consistency checks, separate processes/windows, live SwiftUI tasks, release builds, and strict ad-hoc signature checks. `python3 scripts/check-release.py` additionally checks extracted packages, data preservation, and restart after relocation. Consult the official Release record for the actual results of this release.

## Limitations and pending checks

- Ad-hoc development signature, without Developer ID or Apple notarization. Passing codesign verification is not Apple certification.
- Downloaded Finder/Gatekeeper installation, physical mouse/scroll input, real OS lock/sleep/preferences, multi-display behavior, and visual impressions still require manual checks. Automated or injected events are not real OS interaction coverage.
- Intel and minimum macOS 13 have not been physically tested; the download does not contain an Intel build.
- No automatic updates. Quit the previous version and back up your data before updating. Public packages contain no demonstration or real pet saves.

On a managed Mac, follow the administrator's policy if installation is blocked; do not disable system protection globally. Use Issues for general problems and the private channel in the [security policy](../../SECURITY.en.md) for vulnerabilities and sensitive data.
